# L1-1：Spectre-BHB 同进程原语基线 — 结论卡

> 权威现行版 **v2.2**（已修订并含 v2.1）。来源：对话版原样输出。

**范围(先声明,勿越读):** 同进程、同特权(EL0)自测，受害者间接分支在本进程 `PROT_EXEC` 内存里；用分支历史(BHB)操纵它瞬态误跳到泄露 gadget，L1D Flush+Reload 读出本进程写死的已知靶。**不涉及任何跨进程/跨特权/跨 VM/跨租户，不碰 `pocs/`、`inter_mode`、不改内核、不关缓解。** 对应代码：`vusec/bhi-spectre-bhb@ae_final` 的 `re/arm/bhb_brute_force`（已改）。

## 一句话结论（v2.2）
在倚天 710(Neoverse N2)、同进程 EL0、`cntvct_el0` 计时下，**同进程 in-place BHB 瞬态转向真实存在、推测依赖、可复现**（存在性=success，定论）。v1.0 的 `fail/E004` 被推翻——其负结论由 harness 四缺陷造成（尤以 **replay 每次测试只训练 1 次**）。**命中率典型 ~30%（20–40% 带，方差大）**；**BHB 有效深度判「未裁决」**：我们本次用版本 B 的 `bhb_brute_force` harness（度量"过闸 MAIN 中位"）扫 HISTORY_SIZE，六档中位 95% CI 两两重叠、无峰；但这与 calib 包（度量"随机链撞中概率"、30k 测量/档得出峰在 256）**不是同一个量、未正面对跑**，不能相互否定，需在 N2 直接跑 calib.c 复核。与 N2 被 ARM 列入 Spectre-BHB(CVE-2022-23960) 受影响核一致；跨特权 CVE 仍由固件 CSV2+BHB 清除在异常边界缓解。

## 存在性证据链（闭合，定论）
| 闸门 | 观测 | 读作 |
|---|---|---|
| POS（强制间接分支架构真跳 hit_gadget） | ≈100%（99.9–100%，全程） | 测量链路有效 |
| CTRL（误训练到安全 ret_gadget） | 0%（全程，所有 run） | 不误训练不漏，排除噪声底 |
| NOSPEC=1（ftable 不 flush，`br x0` 立即解析，窗口塌） | SELF 0.0% | 漏点依赖推测窗口 |
| MAIN（训练 hit_gadget，测 ret 链是否误跳） | 窗口开时显著 >0（典型 ~30%，偶达 90%） | 真瞬态误跳 |

**关键严密性**：MAIN 的训练会架构性地把 `fr_buf` 读入缓存再 flush；NOSPEC=1 保留同样的训练+flush、只去掉窗口 → 归零。故 MAIN 信号**不是训练残留假阳性，必须经过推测路径**。

## 根因（v1.0 fail 为何是假负）
原 replay 块对 MAIN/CTRL 每次测试前只调用 1 次 `hit_ptr`，而搜索循环/SELF 训练 128 次。分支预测器误训练需多次迭代饱和，训练 1 次打不偏预测器 → MAIN 塌到 0.1%。补训练循环(TRAIN=128)+THR=5+cntvct 后 MAIN 立即从 ≈0 变为显著 >0。

## 压方差复测（bhb_brute_force harness: governor=performance, TRAIN=128, SHARE=1, N=150/档=900, SELF≥30 且 CTRL=0 且 POS≥99 过闸, 中位 95% bootstrap CI）
| H | pass/N | med | CI_lo | CI_hi | p25 | p75 |
|---|---|---|---|---|---|---|
| 32 | 38/150 | 35.7 | 18.7 | 46.1 | 8.6 | 54.3 |
| 64 | 46/150 | 31.0 | 20.5 | 44.7 | 10.2 | 65.2 |
| 128 | 33/150 | 26.6 | 17.4 | 49.0 | 8.1 | 58.1 |
| 256 | 40/150 | 17.0 | 9.2 | 28.5 | 7.2 | 48.1 |
| 384 | 47/150 | 22.8 | 7.3 | 30.9 | 4.9 | 49.7 |
| 512 | 42/150 | 40.0 | 22.1 | 59.9 | 9.1 | 75.0 |

**解读：**
- **幅度**：过闸 med 约 20–40%，典型约 30%；单 run ~5%–75%。点估计偏软。
- **深度未裁决**：这套 harness + "过闸 MAIN 中位"度量下，六档 CI 两两重叠、无峰。**但这不是 calib 的度量**——calib 量的是"随机链撞中概率随历史长度变化"（测 BHB 深度更对口），30k/档得出峰在 256，统计扎实非单发。两套未对跑，故**本结果不能否定 calib 的峰在 256**；深度待跑 calib.c 复核。（附：我们 H=256 中位 17.0 与 calib 主结果均值 17.99 很接近，但我们 H=64/512 也偏高故没形成峰，更像仪器/度量差异。）
- **过闸率低**：钉频 + 900 发仍仅 27% → 噪声在 cntvct 粗分辨率(1 tick≈55 cycle)二值判定层面，非攻击层面。

## 对复现包定量说法的核对（含一处更正）
- **"MAIN 中位 ~65%"（WFY 4.0）**：订正成立，系有利抽样；复测中位约 30%。
- **"峰在 256"（WFY calib 包）**：**此前曾写"系单发噪声/已证伪"，现撤回——错误**。calib 用 `calib.c`（30k/档、主结果 20 万轮，mean 17.99/std 9.07/≥10 占 80%），统计扎实。"单发"是我们自己第一轮快扫的特征，与 calib 无关。我们没跑 calib.c、用的是另一套 harness 与度量，未对跑 → **深度判未裁决，需跑 calib.c**。
- 以上**不影响存在性成立**。

## 尺子(闸门一)
`cntvct_el0`；ruler 自标 cached≈2 / flushed≈9，THR=5。另一口径（删 `fence()`）cached≈1.3/flushed≈8.1→THR=4，**阈值不可跨口径比较**。

## 对 stock vusec 代码的改动（移植 N2）
1. 计时 `pmccntr_el0`→`cntvct_el0`（perf_user_access=0，EL0 读 PMCCNTR SIGILL）。
2. 删 `syscall(442)`。
3. `targets.h` 加 `YITIAN_710`(ARCH=ARMV8, THR=5, STRIDE=4096)；构建 `make CC_ANDROID=gcc TARGET=YITIAN_710`。
4. harness 四缺陷修复：软时钟→cntvct；THR 6→5；TRAIN 8→128；**replay 补训练循环**。新增 NOSPEC/SHARE 开关、SELF 正对照、CTRL/MAIN/POS 受控复跑。

## 复现要点
`cd re/arm/bhb_brute_force` → 编译 → `SHARE=1 TRAIN=128 ITER=50 taskset -c 2 ./main.o`。推测依赖对照 `NOSPEC=1 … | grep SELF`（应≈0）。压方差脚本：`retest_variance.sh`、`retest_hiN.sh`。**深度裁决待跑 calib.c（30k/档扫描 + 异地对照）。**

## 局限与下一步（不影响存在性定论）
- 幅度点估计偏软；深度在本 harness 下无峰但**未经 calib 仪器复核**。
- **了结深度（正道）**：在 N2 跑 **calib.c** 本身（与 calib 包同仪器、同度量），复现/证伪"峰在 256"。
- 定量幅度：请管理员开 `perf_user_access=1`，用 `PMCCNTR_EL0` 细计数。
- 跨特权 CVE-2022-23960 仍在，固件 CSV2(0b0010)+BHB 清除在异常边界缓解；本实验仅覆盖同进程 in-place 原语。
